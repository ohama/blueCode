## v1.2 Requirements (4/4 shipped)

4개 요구사항. 2026-04-24 벤치마크에서 실측된 pain signal 에 각각 대응.

### Tools (Extended)

- [x] **TLX-01**: `edit_file` — exact-string find-and-replace surgical edit ✓ v1.2
  - Input: `{ path: string; oldString: string; newString: string }`
  - Behavior: 0/1/N match-count branches (`Failure "oldString not found"`, success replacement, `Failure "oldString matches N times; refine to make unique"`)
  - Path validation: project root scope (TOOL-02 `write_file` 와 동일)
  - **Outcome**: Phase 8 plan 02 implementation. v1.2 audit identified mental-model gap (32B chained `write_file` after `edit_file`); Phase 9.1 closed via directive system-prompt wording (`edit_file is the ONLY action needed to save changes...`) + code-level loop-injection (`[POST-EDIT CONSTRAINT]` overrides user-prompt explicit tool naming). W1 32B step count: 4 → 3.

- [x] **TLX-02**: `glob_search` — 파일 패턴 finder ✓ v1.2
  - Input: `{ pattern: string; path: string option }` — pattern 예: `"src/**/*.fs"`, `"**/*.md"`
  - Behavior: project root 기준 glob 매칭 파일 경로 목록 반환, 최대 100개
  - Path validation: project root scope; `.gitignore` 미적용 (v1.3+ 고려)
  - **Outcome**: Phase 8. T5 72B benchmark verified `glob_search` adoption replaces `run_shell "find"` pattern.

- [x] **TLX-03**: `grep_search` — 콘텐츠 패턴 finder ✓ v1.2
  - Input: `{ pattern: string; path: string option; fileGlob: string option }`
  - Behavior: regex/fixed-string content match returning `(relativePath, lineNumber, lineContent)`; `fileGlob` filters scope; max 100 results, lineContent 200-char truncate
  - 500ms per-line `RegexMatchTimeoutException` ReDoS guard
  - Path validation: project root scope, `fileGlob` rejects path-separators
  - **Outcome**: Phase 8. Native tool replaces `run_shell "grep -r"` pattern, no security gate friction.

### Tools (Enhancement)

- [x] **TOOL-08**: `read_file` 응답에 파일 bounds 메타데이터 포함 ✓ v1.2 (extended via Phase 9.1)
  - Format: `[file: <path>, lines X-Y of Z, not-truncated|truncated|out-of-range]\n` prefix on `ToolResult.Success` payload
  - Out-of-range preserves raw requested `endLine` (no clamp)
  - **Outcome**: Phase 9 plan 01 implementation. v1.2 audit identified two effectiveness gaps: (a) dispatcher collapsed partial bounds to `None` so `start_line`-only requests never reached out-of-range branch; (b) `truncated` keyword regressed 72B T6 (model interpreted as "request full file"). Phase 9.1 closed via dispatcher default-window arms (`Some s, None → Some(s, s+99)`; `None, Some e → Some(1, e)`) + system-prompt strategy hint for `truncated` (`pick a smaller window — end_line - start_line < 50`). T6 32B/72B step count: 0/3 FAIL → 3/3 PASS for both models.
