## Repo-Level Lessons (v2.5 patterns)

The following recurring patterns solidified across the 6 v2.5 phases and are now load-bearing conventions:

### IPort / ISeam port-template (solidified across 3 phases)

Three consecutive phases applied the same port-injection pattern for TTY-bound adapters:
- Phase 33 (v2.0 baseline): `PlanGate.IKeyReader` — plan-gate keypress injection
- Phase 34: `EditCommand.IEditorLauncher` — $EDITOR process injection
- Phase 35: `PromptReader.IPromptReader` — PrettyPrompt ReadLineAsync injection

Each pattern: (1) define single-method interface in Cli adapter, (2) `realXxx` production implementation, (3) `makeTestXxx` mock implementation, (4) module-level `mutable xxxOverride : IXxx option = None` seam in Repl.fs, (5) `testSequenced` requirement on all tests using the seam. The pattern is now firmly load-bearing for any future TTY-bound Cli adapter.

### Slash dispatcher extension pattern (established Phase 32-02; used in 33, 34)

New arms added ABOVE the `Some (Prompt prompt)` arm; stub arm slimmed as each command is implemented; `printfn` not `AnsiConsole.MarkupLine` for testable output; `let!` inside `task {}` CE for async calls. The REPL dispatcher has grown from 4 arms (Phase 31) to 11 arms (post-Phase 34) with zero regressions on existing arms.

### One-shot plan-mode semantics (Phase 33-01)

`planModeActive` auto-disables after Accept+Execute, Quit, or rejectCount exhaustion. User must re-type /plan for next plan-gated turn. Avoids "stuck in plan-review loop" surprise. The auto-disable sites are at Repl.fs:238, 247, 274, 280.
