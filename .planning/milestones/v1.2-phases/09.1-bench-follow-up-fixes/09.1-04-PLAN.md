**Wording rationale (cite in commit body — first paragraph below the subject line, ~3 lines):**
The original soft hint (`edit_file persists the change. After a successful edit_file, do NOT call write_file with the same path.`) was overridden by 32B's reasoning in two distinct ways observed in `/tmp/bench-v1.2-fixed/v9_1_W1_32b.log:27` and `v9_1_W2_32b.log:32`:
- W1 thought verbatim: `"The file has been edited to fix the bug. Now, I will save the corrected version."` — the model treats edit_file as a buffered change that still needs explicit save. The new wording (`edit_file is the ONLY action needed to save changes`) directly contradicts that mental model with imperative framing.
- W2 thought verbatim: `"...Now, I will verify the changes by reading the updated content."` — the model treats edit_file as a possibly-failed action requiring verification. The second new sentence (`edit_file's success result already confirms the change; do NOT verify with a follow-up read_file.`) closes that loophole. Without this second sentence, W2 would substitute a verification read for the eliminated write and stay at 4 steps (the exact failure mode observed in 09.1-03).

The directive style (`is the ONLY`, `NEVER`, `do NOT`) replaces declarative softness (`persists`, `do NOT ... with the same path`). All-caps used sparingly on three keywords; F# triple-quoted literals do not escape, so the string is verbatim — readability of the prompt block is preserved.
