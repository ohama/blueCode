### AgentLoop.fs — buildMessages signature change

```fsharp
// Before:
let private buildMessages (systemPrompt: string) (userInput: string) (recentSteps: Step list) : Message list =
    ...
    systemMsg :: userMsg :: stepMsgs

// After:
let private buildMessages (systemPrompt: string) (userInput: string) (recentSteps: Step list) (lastEditPath: string option) : Message list =
    ...
    let baseMsgs = systemMsg :: userMsg :: stepMsgs
    match lastEditPath with
    | Some path ->
        let constraintMsg =
            { Role = System
              Content =
                sprintf
                    "[POST-EDIT CONSTRAINT] You just successfully edited %s. The edit is already persisted. ..."
                    path path path }
        baseMsgs @ [ constraintMsg ]
    | None -> baseMsgs
```

## Decisions Made

1. **Option A (loop-injection) chosen over Option B (schema rejection):** Option B would surface as `SchemaViolation` which `callLlmWithRetry` does NOT retry — session terminates with a hard error worse than the 4-step result. Option A has zero blast radius (pure parameter threading, no schema/Domain changes).

2. **Constraint message position is architectural:** The constraint message is appended AFTER the user message in the messages list. In Qwen's Instruct chat template, a System message appearing after a User turn is processed as authoritative new context post-dating the user request. This is the key lever that makes loop-injection more powerful than system-prompt wording.

3. **CompositionRoot directive wording reinstated as defense-in-depth:** Plan 09.1-04 reverted it procedurally under the "if W1 OR W2 fails, revert" rollback rule — not because the wording was harmful. With loop-injection now closing W1, reinstating the wording provides redundancy at near-zero cost (~95 chars in system prompt).

4. **lastEditPath threading is immutable and minimal:** New state flows through `runLoop` as a function parameter (not a mutable field or record extension). Resets to `None` on any non-EditFile call or EditFile failure — the constraint fires only for the one case where it is semantically correct.
