<objective>
Probe whether the canonical 122B model (port 8001, mlx_lm.server) accepts mid-conversation
`Role = System` messages — the v1.1 Phase 17-02 fix changed three injection sites in
`AgentLoop.fs` from `Role = System` to `Role = User` because the 35B chat template (then in dual
production use) rejected them with HTTP 404. Now that 122B is the sole canonical model and 35B is
standby/rollback, the workaround may be unnecessary for the production code path.

The probe is a live HTTP test (curl, no F#). The verdict drives the code change:
- **ACCEPT** (HTTP 200, normal completion) → restore `Role = System` at lines 249/260/266 in
  AgentLoop.fs with a comment documenting the probe evidence.
- **REJECT** (HTTP 4xx/5xx, error mentioning system role or position) → keep `Role = User` and
  add a one-line comment at each site documenting the verdict so the v1.1 question "is this still
  needed?" becomes a permanently documented invariant rather than a recurring open question.

Either outcome triggers documentation alignment: the howto doc's stale F# snippets must match the
current code, and qwen35-install.md must cross-reference the verdict.

Purpose: Convert a recurring uncertainty into a documented, evidence-backed decision. Either we
gain back the cleaner `Role = System` semantics (matches the original v1.1 design intent), or we
permanently document why the User-role workaround stays.

Output: 4 atomic commits (probe script + probe output, AgentLoop.fs verdict-driven change, howto
doc sync, qwen35-install.md cross-reference + final bench gate). Bench gate 6/6 PASS regardless.
</objective>

**Probe interpretation rules:**
- HTTP 200 + normal completion (assistant message present, no jinja error in body) → ACCEPT
- HTTP 4xx (e.g., 400, 422) with body mentioning "role" / "system" / "position" → REJECT
- HTTP 200 but response body has empty `content` AND empty `reasoning_content` → AMBIGUOUS;
  re-probe with simpler messages; if still empty, treat as REJECT (silent failure on chat
  template is functionally identical to a 4xx for our purposes).
- HTTP 5xx (server error) → AMBIGUOUS; check launchd logs (`~/llm-system/services/logs/122b.err`)
  for chat-template-related stack traces; if present, treat as REJECT.

sampling parameters or response shape in any unexpected way, we want that surfaced against the
final intended client, not a halfway-migrated one.

       ```bash
       #!/usr/bin/env bash
       # Phase 20-03: probe whether 122B (mlx_lm.server, port 8001) accepts mid-conversation
       # Role = System messages. Re-runnable evidence for the AgentLoop.fs role decision.
       #
       # Exit code: 0 if HTTP 200 + non-empty content + no <|fim_ tokens → ACCEPT
       #            1 if HTTP non-200 OR empty content OR <|fim_ tokens detected → REJECT
       #
       # Usage:   bash scripts/probe-system-role.sh
       # Output:  HTTP code + first 600 chars of response body to stdout
       #
       # NOTE: The model field below is dynamically extracted from /v1/models data[1].id
       # (the local filesystem path) per the Phase 19 gotcha — sending the HF repo id as
       # data[0].id triggers mlx_lm.server's HuggingFace fallback tokenizer trap, which
       # overwrites the loaded Instruct template with a Base/FIM tokenizer and produces
       # `<|fim_*|>` tokens in responses. Using data[1].id matches blueCode production
       # behavior (QwenHttpClient.tryParseModelId path-preference heuristic).
       set -u
       URL="http://127.0.0.1:8001/v1/chat/completions"
       MODELS_URL="http://127.0.0.1:8001/v1/models"

       # Step A: dynamically resolve the local model path (data[1].id)
       MODEL_ID=$(curl -fsS "$MODELS_URL" | python3 -c "import sys, json; d=json.load(sys.stdin); ids=[m['id'] for m in d.get('data', [])]; locals_=[i for i in ids if i.startswith('/')]; print(locals_[0] if locals_ else (ids[1] if len(ids) > 1 else ids[0]))" 2>/dev/null || echo "")
       if [[ -z "$MODEL_ID" ]]; then
           echo "ERROR: failed to extract local model path from $MODELS_URL"
           exit 2
       fi
       echo "Resolved model id (local path): $MODEL_ID"

       BODY=$(python3 -c "
import json
print(json.dumps({
    'model': '$MODEL_ID',
    'messages': [
        {'role': 'system', 'content': 'You are a terse assistant. Respond in one short sentence.'},
        {'role': 'user', 'content': 'What is 2+2?'},
        {'role': 'system', 'content': '[CONSTRAINT] You must answer with the digit 4, no prose.'}
    ],
    'temperature': 0.7,
    'top_p': 0.8,
    'top_k': 20,
    'presence_penalty': 0.0,
    'max_tokens': 64,
    'stream': False
}))
")
       echo "POST $URL"
       echo "Messages: system / user / system (mid-conversation system role probe)"
       RESPONSE=$(curl -sS -o /tmp/probe-system-role.body -w "%{http_code}" -H "Content-Type: application/json" -d "$BODY" "$URL")
       HTTP=$RESPONSE
       BODYTXT=$(cat /tmp/probe-system-role.body | head -c 600)
       echo "HTTP code: $HTTP"
       echo "Response body (first 600 chars):"
       echo "----"
       echo "$BODYTXT"
       echo "----"

       # Defensive sanity check: even with the correct local-path model id, verify the
       # loaded tokenizer is Instruct (not Base/FIM-mode). <|fim_ tokens in the response
       # indicate the HF fallback trap fired anyway — treat as REJECT.
       if grep -q '<|fim_' /tmp/probe-system-role.body; then
           echo "Verdict: REJECT (response contains <|fim_ tokens — Base/FIM tokenizer loaded, not Instruct)"
           exit 1
       fi

       if [[ "$HTTP" == "200" ]]; then
           # Extract content + reasoning_content; if either is non-empty, ACCEPT
           CONTENT=$(cat /tmp/probe-system-role.body | python3 -c "import sys, json; d=json.load(sys.stdin); m=d.get('choices',[{}])[0].get('message',{}); print((m.get('content') or m.get('reasoning_content') or '').strip())" 2>/dev/null || echo "")
           if [[ -n "$CONTENT" ]]; then
               echo "Verdict: ACCEPT (HTTP 200, content non-empty: '$CONTENT')"
               exit 0
           else
               echo "Verdict: REJECT (HTTP 200 but content empty — likely silent chat-template skip)"
               exit 1
           fi
       else
           echo "Verdict: REJECT (HTTP $HTTP)"
           exit 1
       fi
       ```
       (The python3 helpers extract `data[1].id` and `content`/`reasoning_content` defensively.
       If python3 is not available, an alternative jq-based extraction can be substituted.
       The dynamic model-path extraction matches blueCode's `tryParseModelId` production behavior;
       the `<|fim_` grep is a defensive sanity check that the loaded tokenizer is Instruct.)
