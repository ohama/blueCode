# Requirements: blueCode v2.1 Empirical Qwen 3.5 122B Coding Evaluation

**Defined:** 2026-04-27
**Core Value:** Mac 로컬 Qwen 3.5 122B를 strong-typed F# agent loop로 안정적으로 돌린다 (single-model canonical post-v2.0)
**Milestone goal:** Produce empirical answers to "is Qwen 3.5 122B-A10B-4bit MoE useful for daily coding?" via comprehensive measurement across correctness, performance, reliability, and coding-specific quality dimensions. Deliver `documentation/qwen35-122b-coding-eval.md` with 100-point scorecard verdict and KEEP / KEEP-WITH-CAVEATS / ESCALATE recommendation.

## v2.1 Requirements (10 requirements, 4 categories — ALL Complete)

Each requirement is empirical, measurable, and produces a verdict line in the final eval doc.

### Performance

- [x] **PERF-EVAL-01**: Tokens/sec throughput
  - **Result:** Median 34.6 tok/s (range 31.29-34.88) across 5 prompts × 3 trials. ≥30 threshold met.
  - **Score:** 10/10 pts (top band)
  - **Artifact:** `bench/runs/qwen35-eval-20260428-052719/throughput.json` (15 entries)

- [x] **PERF-EVAL-02**: Time-to-first-token (TTFT)
  - **Result:** Median 222 ms warm (trial-1 cold 929 ms; trials 2-10 stable 214-230 ms). ≤500 ms threshold met.
  - **Score:** 5/5 pts
  - **Artifact:** `bench/runs/qwen35-eval-20260428-053114/ttft.json` (10 entries)

### Correctness

- [x] **CORR-EVAL-01**: HumanEval+ pass@1 (chat + completion modes)
  - **Result:** Chat pass@1 = **0.939** / pass@1+ = **0.902** (154/164 chat-mode); completion pass@1 = 0.226 / pass@1+ = 0.213 (informational). Chat mode is what blueCode actually uses at runtime.
  - **Score:** 15/15 pts (≥75% top band)
  - **Artifact:** `bench/runs/qwen35-eval-20260428-055057/humaneval_results.json` (328 entries; 164 × 2 modes)
  - **Notable:** Two macOS evalplus scoring traps diagnosed and fixed: (1) `evalplus.sanitize` pre-pass for chat-mode doubled signatures; (2) `EVALPLUS_MAX_MEMORY_BYTES=-1` env var to skip RLIMIT_AS hard-limit crash. Both baked into `run_humaneval()`.

- [x] **CORR-EVAL-02**: Multi-file F# refactoring fixture
  - **Result:** **FAIL** — orphan_count=1 in `refactor_orphan_count.txt`. Agent read all 4 files coherently (steps 1-4) and started rename on Calculator.fs (step 5: `add3` → `sum3`), then exhausted 5-step PLAN-04 budget before touching Main.fs/Tests.fs. Real eval signal: multi-file refactor structurally requires 7+ steps; not a model failure.
  - **Score:** 0/5 pts (all-or-nothing FAIL)
  - **Artifact:** `bench/runs/qwen35-eval-20260428-093852/refactor_multifile_diff.txt` + `refactor_orphan_count.txt`
  - **v2.2 trigger:** Eval doc §9 lists "if 5-step cap is raised, re-run CORR-EVAL-02" as re-evaluation criterion.

- [x] **CORR-EVAL-03**: Algorithm-level F# bug-fix (binsearch off-by-one)
  - **Result:** Qualitative PASS — agent correctly identified `hi <- mid` (should be `hi <- mid - 1`) and named triggering input `[|1;3;5|]` with target `4`. 2 steps, 9s.
  - **Score:** 3.75/3.75 pts (one of 4 F# bug-fix slots)
  - **Artifact:** `bench/runs/qwen35-eval-20260428-094337/bug_binsearch_diagnose.log`

- [x] **CORR-EVAL-04**: Language coverage (Python + TypeScript)
  - **Result:** Both qualitative PASS. Python parse_age: silent None on TypeError + negative; triggering input `['25', 'not_a_number', '30']`. TypeScript fetchAllUsers: missing `await Promise.all(promises)`; triggering input any non-empty number array. Each 2 steps, ~8s.
  - **Score:** 5/5 pts (2.5 each × 2 PASS)
  - **Artifacts:** `bug_python_typeerror_diagnose.log` + `bug_typescript_async_diagnose.log` in same LOG_DIR

### Reliability

- [x] **REL-EVAL-01**: JSON schema compliance rate
  - **Result:** **0/50 InvalidJsonOutput** (perfect). Stricter than Phase 18-02's 0/31. Mix of T1+T6-style prompts.
  - **Score:** 10/10 pts (≥49/50 top band)
  - **Artifact:** `bench/runs/qwen35-eval-20260428-095606/schema_rate.txt` + 50 per-iteration logs in `schema_logs/`
  - **Deviation auto-fixed:** `grep -c || echo 0` under `set -euo pipefail` produced double-output and aborted cross-check pipeline; fixed to `|| true`.

- [x] **REL-EVAL-02**: Multi-turn degradation curve
  - **Result:** Stable through N=7. N=1: 1 step clean ×3. N=3: 3 steps clean ×3. N=5: MaxLoopsExceeded at turn 4 ×3 (parametrize prompt too complex for 5-step budget — same PLAN-04 ceiling as CORR-EVAL-02). N=7: 6/7 steps clean. N=10: 5/10 steps with invalid_json=2 at turns 7-10. **Refutes mlx-lm#1011 "approximately 5 rounds" claim** in our environment (mlx_lm.server + thinking-mode-off + Role=User invariant).
  - **Score:** 10/10 pts (stable through 7+)
  - **Artifact:** `bench/runs/qwen35-eval-20260428-100537/multiturn_N{1,3,5,7,10}/`
  - **Deviation auto-fixed:** macOS BSD `seq 2 1` returns countdown `"2 1"` (not empty as GNU); `run_multiturn` N=1 ran 3 turns instead of 1. Fixed with `[ n -ge 2 ] && seq 2 n || true` guard.

- [x] **REL-EVAL-03**: Long-context needle-in-haystack
  - **Result:** **4/4 retrieved** at 8k/16k/32k/32768 tokens. max_model_len=32768 (mlx_lm.server fallback — field not exposed in `/v1/models` for this server version). Default `--sizes 8000,16000,32000,65536` capped to ceiling, dedup yielded 4 unique entries on this server.
  - **Score:** 5/5 pts
  - **Artifact:** `bench/runs/qwen35-eval-20260428-100057/needle.json`

### Documentation

- [x] **DOC-EVAL-01**: `documentation/qwen35-122b-coding-eval.md`
