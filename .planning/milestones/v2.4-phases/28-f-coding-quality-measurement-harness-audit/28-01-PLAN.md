Mirror the conventions from sibling howto files (e.g., `documentation/howto/handle-expecto-console-redirection.md`, `documentation/howto/iterate-llm-prompts-with-bench-driven-validation.md`):
- H1 title: `# macOS bash-strict-mode patterns for harness scripts`
- Brief intro (2-3 sentences): when `set -euo pipefail` interacts with macOS BSD utilities and child-process exit codes, harmless conditions become script-aborting failures. This howto enumerates the 4 patterns we hit across v2.1-v2.3 plus the canonical fix for each.
- "Common rule" callout near the top: `set -euo pipefail` + macOS BSD utilities = aggressively guard PASS-path control flow.

Then 4 sections (one H2 per pattern). Each section has the following structure:

### Pattern N: <short name>

- **Symptom:** What the user sees (e.g., "Script aborts with exit 1; no error message; previous lines worked fine").
- **Root cause:** One paragraph explaining WHY (e.g., "`grep -c` returns exit 1 when the file contains zero matches; under `set -e` this aborts the script even though zero matches is the PASS condition").
- **Canonical fix:** Code block (~3-8 lines) showing the fix verbatim.
- **Reference:** `bench/eval-qwen35-122b.sh` line numbers + commit hash.

The 4 patterns (use research Q1 + Q7 verbatim; line numbers as of current state):

**Pattern 1: `set -e` aborts on `dotnet run` non-zero exit (MaxLoopsExceeded is data, not failure)**
- Symptom: Harness aborts mid-run; final transcript truncated; bench gate cannot read fixture state.
- Root cause: `dotnet run` exits 1 when the agent hits `MaxLoopsExceeded` (data we want to capture, not a script failure). With `set -e`, any non-zero exit aborts immediately.
- Canonical fix:
  ```bash
  set +e
  /usr/bin/time -p dotnet run --project src/BlueCode.Cli -- --verbose --model 122b "$prompt" >> "$out" 2>&1
  local exit_code=$?
  set -e
  ```
- Reference: `bench/eval-qwen35-122b.sh:272-277` (run_refactor); same pattern at lines 329-332, 394-397, 434-436. Commit `4bcd8a4` (v2.1 21-04 first introduction).

**Pattern 2: `grep -c` exit-1 on zero matches under `pipefail`**
- Symptom: Script aborts on grep call that previously worked; aborts in subshell when piped to `awk`.
- Root cause: `grep -c` exits 1 when zero lines match. Under `set -euo pipefail`, the failure of any command in a pipe (including a producer) aborts the script. The PASS condition (zero `InvalidJsonOutput` errors observed in a 50-iteration smoke run) becomes a fatal error.
- Canonical fix: append `|| true` to suppress non-match exit code, OR wrap in subshell `( ... || true )`:
  ```bash
  block_invalid=$(grep -c "InvalidJsonOutput" "$iter_log" 2>/dev/null || true)
  ```
- Reference: `bench/eval-qwen35-122b.sh:438-441` (run_schema_rate per-iteration); also lines 295-300 (run_refactor orphan count subshell). Commit `4bcd8a4` (v2.1 21-04).

**Pattern 3: `mkdir -p` must precede any `tee` / output redirect to a subdirectory of `$LOG_DIR`**
- Symptom: `tee: <path>: No such file or directory`; sometimes silently truncates output.
- Root cause: `tee` and shell redirect `>` do not auto-create parent directories. Under `set -e`, the failed open is a fatal abort.
- Canonical fix: `mkdir -p "$LOG_DIR/<subdir>"` immediately before any I/O command that writes to that subdir. For multi-handler scripts, call `mkdir -p "$LOG_DIR"` at the top of every handler that may run standalone.
  ```bash
  mkdir -p "$logs_dir"
  echo "===== $label =====" > "$iter_log"
  ```
- Reference: `bench/eval-qwen35-122b.sh:415` (run_schema_rate creates `$logs_dir` before per-iter writes); convention enforced across handlers via `mkdir -p "$LOG_DIR"` first line of every `run_*` function. Commit reference: v2.2 23-01 (HARNESS-AUDIT discovery; cite plan SUMMARY).

**Pattern 4: `grep -cE` zero-match still aborts under `set -e` even with `2>/dev/null`**
- Symptom: Script aborts on grep call that returns 0 matches when the surrounding logic was treating zero-matches as a PASS.
- Root cause: Same root as Pattern 2 (`grep` exits 1 on zero matches), but specifically biting in subshells where `set -e` propagates. `2>/dev/null` only suppresses stderr; it does NOT change the exit code.
- Canonical fix: wrap the grep call in `( ... || true )` inside the subshell so the exit code is normalized to 0 BEFORE the subshell substitution captures it:
  ```bash
  orphan_count=$( (grep -cE '\b(let |Calculator\.)add\b' \
      "$fixture_dir/Calculator.fs" \
      "$fixture_dir/Main.fs" \
      "$fixture_dir/Tests.fs" 2>/dev/null || true) | awk -F: '{sum+=$2} END {print sum+0}')
  ```
- Reference: `bench/eval-qwen35-122b.sh:295-300` (run_refactor PASS-path orphan count). Commit `9f8e06e` (v2.3 Phase 27-02 discovery + fix).

**Pattern 5 (optional, only if Task 1 found a 5th case OR if `seq M N` countdown is judged worth documenting):**

If Task 1 surfaced a 5th unhandled strict-mode bug, document it here with the same structure. If `seq M N` countdown was already mitigated (line 390) but worth documenting:

**Pattern 5: BSD `seq M N` counts DOWN when M > N (vs GNU `seq` which emits empty)**
- Symptom: Loop iterates with reversed values when N=1; spurious extra iterations.
- Root cause: macOS BSD `seq 2 1` outputs `2 1` (counting down), while GNU `seq 2 1` outputs nothing. Loops written assuming GNU semantics misbehave.
- Canonical fix:
  ```bash
  for k in $([ "$n" -ge 2 ] && seq 2 "$n" || true); do ... done
  ```
- Reference: `bench/eval-qwen35-122b.sh:390` (run_multiturn turn loop). Commit reference: v2.1 21-04 plan SUMMARY.

Close with a "Cross-references" section pointing to:

- Sibling howto: `documentation/howto/iterate-llm-prompts-with-bench-driven-validation.md` (when to add a new pattern: any harness PR that adds `|| true` is implicitly fixing one of these).

Total length: 150-300 lines (research Q7 spec).
