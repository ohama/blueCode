Outcome: `documentation/qwen35-122b-coding-eval.md` (983 lines, 10 sections) ending with **Total: 82/100, Recommendation: KEEP**. HumanEval+ chat pass@1 = 0.939 / pass@1+ = 0.902 places Qwen 3.5 122B-A10B-4bit MoE in the upper tier of open-weight coding models; schema compliance 0/50 perfect; multi-turn coherence through N=7 (refutes mlx-lm#1011 "approximately 5 rounds" community claim); needle 4/4 retrieved at max_model_len=32768. Multi-file refactor FAIL (orphan_count=1) is a real eval signal — not a model failure but a 5-step PLAN-04 architectural ceiling discovery, surfaced for v2.2 scoping.

## Milestone Summary

**Decimal Phases:** None (single-phase milestone).

**Key Decisions:**

- v2.1 formalized as GSD milestone (not ad-hoc tooling) — atomic commits per task, phase verifier, audit. Outcome: ✓ Good — milestone shipped clean with 82/100 KEEP verdict; verification 15/15 truths verified.
- Hybrid bash + Python(venv) approach — pure-bash for performance/reliability/refactoring; Python for HumanEval+ scoring (evalplus non-negotiable) and needle. mlx-runner's in-process `mlx_lm.load()` would OOM. Outcome: ✓ Good — HTTP-only constraint preserved; no second 122B instance loaded.
- HumanEval+ both modes (chat + completion) — chat is "useful for blueCode" headline; completion is direct compare-to-published. Outcome: ✓ Good — chat 0.939 headline; completion 0.226 informational; chat-wrapping artifact (explanation+code instead of raw code) made completion-mode lower as expected.
- 100-point scorecard verdict (40/25/25/10) with explicit thresholds — coarse PASS/FAIL hides which dimension is weak. Outcome: ✓ Good — 82/100 lands cleanly in KEEP band; Coding quality at exactly 60% threshold surfaces the F# idiomaticness caveat.
- Cloud comparison explicit non-goal — API key + cost dependency, scope drift, user has muscle memory from daily Claude Opus use. Outcome: ✓ Good — boundary held; documented in eval doc §6.3 with full rationale.
- macOS evalplus traps require sanitize + RLIMIT_AS env override — chat-mode doubled signature breaks parsing; RLIMIT_AS exceeds macOS hard limit. Outcome: ✓ Good — both fixes baked into `run_humaneval()`; without them silent pass@1=0.
- 5-step PLAN-04 ceiling = constraint discovery — CORR-EVAL-02 FAIL (orphan_count=1) reveals genuine multi-file refactor needs 7+ steps. Outcome: ⚠ Revisit — v2.2 first candidate; not a code bug; eval doc §9 lists "if 5-step cap is raised, re-run CORR-EVAL-02" as re-evaluation trigger.
- macOS BSD `seq 2 1` countdown + `set -euo pipefail`/`grep -c` interactions documented — both surfaced as auto-fix deviations. Outcome: ✓ Good — patterns documented in plan SUMMARYs for future bash handler authors.

**Issues Resolved:**

- v2.0 measurement gap closed — empirical anchor benchmarks (HumanEval+, tok/s, TTFT, multi-turn, needle, multi-file, language coverage) all now have data.
- mlx-lm#1011 "5 rounds" community concern empirically reviewed — multi-turn coherence through N=7 in our environment (mlx_lm.server + thinking-mode-off + Role=User invariant). Issue claim does not apply.
- 3.4× speedup claim from Phase 17 SWITCH backed by real tok/s measurement (34.6 tok/s median).
- Two macOS evalplus silent-failure traps (sanitize + RLIMIT_AS) diagnosed and fixed; reproduction now reliable.
