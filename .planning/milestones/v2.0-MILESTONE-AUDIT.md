# v2.0 Milestone Audit: Persistence + Planning

**Milestone:** v2.0 Persistence + Planning

## Executive Summary

The v2.0 milestone delivers its stated goals cleanly. All 8 functional requirements (PERSIST-01..04, PLAN-01..04) are verified complete across phases 14-16. Phases 17-20 execute a model-upgrade and protocol-alignment arc that was unplanned at milestone scoping but correctly sequenced and completed before Phase 16's bench fixtures were committed. Six cross-phase E2E flows — multi-turn memory, persistence round-trip, plan-then-execute, plan + persistence combined, single-model invariant chain, and protocol alignment — all verify empirically: `dotnet run` reports 282/1/0 and `bench/run.sh --gate` exits 0 with 7/7 PASS (confirmed live during this audit). The only meaningful audit finding is a documentation drift cluster: Phase 20 completed without the orchestrator running `gsd-verifier`, leaving ROADMAP.md with a stale `[ ]` checkbox and Progress table row. This is a process artifact gap, not a code gap — Phase 20's three per-plan SUMMARYs plus the bench gate 6/6 PASS recorded after each plan constitute functionally equivalent verification. No integration breaks, no orphaned exports, no missing API consumers, no unprotected routes were found. Tech debt is expected and proportionate: plan-mode bench fixture deferred due to intractable Console.ReadKey UX, plus four v2.1+ protocol items (thinking-mode-on, native tool_calls, additionalProperties relaxation, max_tokens bump).

## Tech Debt Aggregation by Phase

### Phase 14: Domain Extensions
No debt. Pure Foundation layer — types, validator, port. Correctly scoped; schema validation deferred to Phase 16 Cli adapter as designed.

### Phase 15: Persistence Wiring
**Compaction risk (low, expected):** SESSION JSONL is append-only with no compaction. Long sessions accumulate unbounded context, driving the LLM toward the 80% context window warning faster. Documented in STATE.md Blockers/Concerns and REQUIREMENTS.md Out-of-Scope. v2.1 candidate COMPACT-01.

### Phase 16: Planning Wiring + Bench
**Plan-mode bench fixture deferred (low):** PlanGate's `Console.ReadKey` UX is intractable for autonomous regression gate. Coverage substitute (PlanGateTests + PlanParseTests + runPlanTurnTests) is documented in bench.md with 4-point rationale. Acceptable — interactive approval gates are inherently non-automatable.

**REPL plan-mode deferred (low):** `--plan` is per-invocation only; per-turn `/plan` slash command requires v2.1 REPL redesign. Acceptable scope boundary.

### Phase 17: Qwen 3.5 Evaluation
**Cold-start timing gap (info):** 17-02-LOAD-TEST.md §6.1 estimated (not measured) cold-start wall-clock for 35B (30-60s) and 122B (120-240s). Phase 20-01 subsequently raised HttpClient.Timeout to 300s based on 240s empirical observation, closing the operational concern. The documentation gap persists as a minor historical note.

**SHIP-BOTH deferred (info):** No per-task split benefit observed in bench data. Deferred to v2.1+. Not a gap — the evaluation was done and the data supported the deferral.

### Phase 18: Single-Model 122B Evaluation
No open debt. Compressor monitoring concern raised in 17-02 (543 MB) was verified resolved by Phase 18 (454 MB post-bench, below 1 GB threshold).

### Phase 19: Qwen 2.5 Retirement
**Stale v1.1 Key Seams text (info):** CLAUDE.md `## Key Seams (v1.1)` §Bootstrap reads "If the user targets only 72B, port 8000 is never contacted" — stale since the section describes v1.1 internals as historical context. The `## Runtime Environment` section is correctly updated. Both Phase 19 and 19-VERIFICATION flag this as non-blocking.

### Phase 20: Protocol Alignment
**v2.1+ protocol items (low):** Four architectural improvements explicitly out-of-scope and deferred: `enable_thinking: true` mode (requires `max_tokens` bump + re-bench), OpenAI native `tool_calls` (rewrites all bench fixtures), `additionalProperties: false` relaxation, `max_tokens` budget revision. All four are documented in ROADMAP.md §Phase 20 "Out of scope" section and in STATE.md Pending Todos.
