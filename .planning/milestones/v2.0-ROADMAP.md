# Milestone v2.0: Persistence + Planning

**Status:** ✅ SHIPPED 2026-04-27
**Phases:** 14 - 20 (7 phases, including 3 added mid-milestone via `/gsd:add-phase`)
**Total Plans:** 19 (across 7 phases)

## Overview

v2.0 broke the process-lifetime constraint that v1 deliberately accepted. Bundled cross-turn REPL memory + `--resume <id>` (PERSIST-01..04) with plan-then-execute mode + user approval gate (PLAN-01..04). The two features shared an architectural root (state outside a single `runSession`) and shipped together by design.

The milestone expanded mid-flight: original 3-phase scope (14-16) grew to 7 phases as Qwen 3.5 model evaluation (Phase 17) → Single-Model 122B viability (Phase 18) → Qwen 2.5 retirement (Phase 19) → Qwen 3.5 protocol alignment (Phase 20) sequenced ahead of Phase 16. The model-platform shift was orthogonal to the persistence/planning theme but landed in the same milestone because Phase 16's bench fixtures depended on the canonical model pair being settled.

**Phase numbering:** Continued from v1.4's Phase 13 (v1.0: 1-5; v1.1: 6-7; v1.2: 8/9/9.1; v1.3: 10-11; v1.4: 12-13).

## Milestone Summary

**Decimal Phases:** None.

**Mid-milestone scope expansion:** v2.0 grew from 3 phases (14-16) to 7 phases via 4 `/gsd:add-phase` invocations. The model-platform shift (Phases 17-20) was orthogonal to the persistence/planning theme but landed in the same milestone because Phase 16's bench fixtures depended on the canonical model pair being settled. Phase 16 was REPLANNED FROM SCRATCH after Phases 17-20 shifted the architectural premises (32B/72B → 122B single-model; baseline 8→6 entries; sampling params; Role=User invariant).

**Key Decisions:**

- **v2.0 (architectural)**: Bundle persistence + planning together. Memory without planning gives long-context drift; planning without memory gives brilliant single-turn agents that forget yesterday. Justified by mid-milestone evidence — Phase 16's `--plan --resume <id>` SC4 verifies the bundle works end-to-end.
- **Phase 14 (atomic Domain shift)**: Single Phase 14 commit captured all v2.0 type-level work (Session, Plan, ISessionStore, AgentError variants). Mirrored v1.1's "big-bang LlmResponse compile cascade" pattern.
- **Phase 14 (PlanValidator scope)**: Validator handles 3 structural rules (length, unknown tool, duplicate adjacent); schema-invalid input deferred to Phase 16 JSON parse layer (where JsonSchema.Net lives in BlueCode.Cli/Adapters/, outside Core purity boundary). ROADMAP SC3/SC4 corrected mid-verification.
- **Phase 15 (Argu flag aliases)**: Argu converts `NewSession` DU case to `--newsession`. Added `[<AltCommandLine("--new-session")>]` so both forms work. Same pattern repeated for `--with-35b`/`--withdual` in Phase 19.
- **Phase 17 (SWITCH)**: Qwen 3.5 35B/122B replaces 32B/72B as canonical. 3.4× speedup. **Phase 17-02 mid-execution discovery: Qwen 3.5 chat template REJECTS mid-conversation Role=System with HTTP 404. Mid-conversation injections flipped to Role=User.** This invariant is load-bearing for all v2.0+ work.
- **Phase 18 (DROP-35B)**: 122B alone is viable canonical. RSS flat under bench load (MoE expert routing converges on stable subset). PhysMem +19.42 GB freed. Architectural follow-ups deferred to Phase 19.
- **Phase 19 (single-model + breaking CLI changes)**: `--model 32b/72b` aliases REMOVED entirely (exit 2 with retirement error). `--with-35b` opt-in flag for future dual mode. `bench/run.sh` absorbed `scripts/bench-122b-only.sh`. Disk -85 GB.
- **Phase 20-03 (Role=User probe)**: Re-probed 122B with mid-conversation Role=System; REJECT verdict (HTTP 404). Phase 17-02 fix vindicated and now applies to 122B alone too. AgentLoop.fs `Role = User` documented in 3-line code comments at lines 249/260/266.
- **Phase 16 replan-from-scratch**: After Phases 17-20 shifted premises (32B/72B → 122B; 8→6 baseline; new sampling params; Role=User invariant), the original Phase 16 plans were too stale to surgically re-key. Replanned cleanly. Stale `.stale` siblings preserved as forensic reference.
- **Phase 16 [PLAN REJECTED] role**: Re-prompt is delivered as part of next user-prompt turn (Role=User by definition), NOT a Role=System mid-conversation message. Phase 20-03 invariant honored.
- **Phase 16 plan-mode bench DEFERRED v2.1+**: Keystroke-driven UX (`Console.ReadKey(true)`) intractable for autonomous regression gate. PlanParseTests + PlanGateTests + AgentLoopTests substitute via mocked IKeyReader.
