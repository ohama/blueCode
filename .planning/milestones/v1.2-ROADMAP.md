# Milestone v1.2: Tool Expansion

**Status:** ✅ SHIPPED 2026-04-26
**Phases:** 8 - 9 + 9.1 (decimal insertion)
**Total Plans:** 8 (3 original + 5 in inserted Phase 9.1)

## Overview

v1.2 added three new agent tools (`edit_file`, `glob_search`, `grep_search`) and one `read_file` metadata enhancement (TOOL-08), motivated by four measured pain signals from the 2026-04-24 benchmark session. Phase 8 introduced the new tools across the full Tool DU + schema enum + executor + system prompt stack. Phase 9 added a structured one-line metadata header to every `read_file` response. Phase 9.1, inserted post-audit after a same-day live re-bench surfaced effectiveness gaps in T6 (32B + 72B) and W1/W2 (32B), shipped a multi-layered fix: dispatcher default-window, system-prompt strategy hint for `truncated`, directive `edit_file` terminal wording, and — when wording-only intervention proved insufficient against user-prompt explicit tool naming — a code-level loop-injection mechanism (`[POST-EDIT CONSTRAINT]` System-role message threaded through `runLoop`).

## Milestone Summary

**Decimal Phases:**

- Phase 9.1: Bench Follow-up Fixes (inserted after Phase 9 via `/gsd:insert-phase`, post-audit re-bench surfaced T6 + W1/W2 gaps)

**Key Decisions:**

- **read_file metadata header uses input `path` (relative), never `resolved` (absolute)** — preserves CLAUDE.md no-absolute-paths invariant
- **Out-of-range branch preserves the RAW requested `endLine`** (no clamp to `totalLines`) so the bounds-violation signal is unambiguous to the LLM
- **Unified `readFileImpl` on `File.ReadAllLines`** (eager array) replacing the prior mix of `ReadAllText` + `ReadLines`
- **Test substring assertions for line content must anchor with `\n`** — header words like `truncated` (contains `a`), `lines` (contains `e`) collide with body text; pattern generalizable for any tool that prepends a fixed-format header
- **`dotnet test` does NOT run Expecto in this project** — canonical runner is `dotnet run --project tests/BlueCode.Tests/BlueCode.Tests.fsproj`
- **Dispatcher default-window** — `Some(s, s+99)` for start-only, `Some(1, e)` for end-only; arms ordered between full-bounds match and `| _ -> None` wildcard (F# match exhaustiveness preserved)
- **System-prompt strategy hint for `truncated`** — restored 72B's pre-v1.2 narrow-window heuristic that the explicit `truncated` keyword had overridden
- **User-prompt explicit tool naming overrides system-prompt directive wording** (09.1-04 discovery) — wording-only intervention class is exhausted when the bench fixture explicitly says "using write_file"; code-level enforcement is required
- **Loop-injection mechanism (09.1-05)** — `lastEditPath: string option` threaded through `runLoop`; `buildMessages` appends a System-role `[POST-EDIT CONSTRAINT]` message at the END of the message list when prior step was `edit_file Success`; conversation-history position (post-user) makes the constraint authoritative against any prior user instruction. Reusable primitive for future tool-terminality concerns
- **Bench discipline** — `/gsd:audit-milestone` revealed gaps not surfaced by phase-level verification; phase verifiers should require live behavioral tests (probe-style) for any requirement whose evidence claim cites a specific failure trace
