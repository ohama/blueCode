## Lessons (for future milestones)

1. **Measurement-first scoping is sometimes a free win.** When a prior score is based on category-mismatched evidence (HumanEval+ Python answers scored as Idiomatic F#), proper category-matched fixtures may yield a higher score with no code change. v2.4 added +4 points without modifying `src/`. Worth recognizing this pattern: *"is the score real, or is the measurement instrument wrong?"* — applies to any benchmarking dimension.

2. **Conditional phase SKIP is a valid milestone path.** v2.4 Path A (Phase 29 SKIP-by-design) is structurally cleaner than v2.3 Path A (Phase 26 BLOCKED-with-record). When a conditional phase is genuinely conditional (not partial-attempt), let it skip without creating a phase directory. The `passed_disprove_1of5` classification at the end of Phase 28 was the load-bearing decision artifact.

3. **Sum-then-scale band tables beat round(average) for multi-fixture rubrics.** Phase 28-04 caught this in the iter-1 plan-checker pass (BLOCKER 2). For [5,5,0]: average rounds to 3 (loses signal); sum-band gives 4 (preserves signal). When designing aggregate scoring across small fixture sets, the band table approach is more robust to outliers.

4. **HARNESS-AUDIT bundling is a good v.X close pattern.** Wrapping `documentation/howto/macos-bash-strict-mode-patterns.md` into Phase 28 (same harness file as the new `--fs-idiomatic` mode) cost ~30-60 min and produced a discoverable artifact for future bash handler authors. The pattern: *small standalone docs/cleanup tasks bundle naturally with phases that touch the same file*.

5. **Zero-source-diff milestones are real.** v2.1 (eval infrastructure), v2.4 (F# fixture infrastructure + scoring) — both shipped meaningful capability without touching `src/`. The `git diff milestone-v<prev> HEAD -- src/` empty assertion is now an established invariant pattern; future milestones can lean on it for low-risk eval/measurement work.

6. **Plan-checker quota exhaustion is OK to absorb when plan structure is well-templated.** During v2.4 (and earlier in v2.3), opus checker quota ran out twice. Self-applied quality gate (planner's pre-return checklist) plus structural mirror with prior canonical close-plan (v2.3 Phase 25-03 / 27-03) was sufficient. Phase 30 executed cleanly without checker review. The risk model: when the plan is procedurally simple and the executor has executed close-plans before, the checker's marginal value is low.
