**Exact insertion (use Edit tool — read file first, then targeted insert):**

After line 14 (`set -u`), insert these THREE lines (the trap line plus a leading blank line and a trailing comment for readability):

```bash

# Auto-reset W1/W2 write-task fixtures on exit (success, failure, or Ctrl-C).
# bug_divide_zero.fs is read-only by design (B2 diagnose); do NOT include it here.
trap 'git checkout -- bench/fixtures/bug_lastchar.fs bench/fixtures/bug_average.fs 2>/dev/null || true' EXIT
```

Result: `set -u` on line 14, blank line 15, two comment lines 16-17, `trap '...' EXIT` on line 18, `cd /Users/ohama/projs/blueCode` shifts to line 19. The rest of the file is unchanged.

**Hard constraints (do not violate):**
- DO NOT add `set -e` — existing convention is `set -u` only (CLAUDE.md / STATE.md note: bash 3.2 compat, `set -u` only).
- DO NOT include `bench/fixtures/bug_divide_zero.fs` in the trap — it is the B2 read-only diagnose fixture, never modified by any test. Including it would be wrong.
- DO NOT touch the existing in-line heredoc-restore blocks at lines 133-151 (gate W1+W2) or lines 274-292 (write_W1, write_W2). These remain unchanged; the trap and the heredocs are intentional defense-in-depth (heredoc = between-invocation reset; trap = exit-time safety net).
- DO NOT call `exit N` inside the trap body — bash automatically preserves the original exit code as long as the trap does not call `exit`. The `git checkout ... 2>/dev/null || true` form does not call `exit`, so exit code preservation is automatic.
- The `|| true` guard ensures the trap never crashes the script if `git` is unavailable or if the fixtures are not yet tracked.
- Bash 3.2 compat: `trap '...' EXIT` is portable to bash 3.2 (macOS default). Single-quote the trap body so `$VAR` expansion happens at trap-fire time, not parse time (here there are no variables, but follow the convention).

**Sanity check after edit:** Run `bash -n bench/run.sh` — must exit 0 (syntax OK).

defense-in-depth: heredoc handles between-invocation reset within a single run;
the trap handles exit-time cleanup. Either alone is sufficient; together they
guarantee a clean working tree under every reasonable failure mode.
