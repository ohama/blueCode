# Requirements: blueCode v1.3 Bench-Driven Quality Gates

**Defined:** 2026-04-26
**Core Value:** Mac 로컬 Qwen 32B/72B를 strong-typed F# agent loop로 안정적으로 돌린다
**Milestone goal:** Lock in v1.2's behavioral wins as a regressable suite, then use that suite to validate a system-prompt shrink that closes the B2 regression and creates headroom for future tools.

## v1.3 Requirements (8/8 shipped)

### Bench

- [x] **BENCH-01** ✓ v1.3 — `bench/run.sh` repo-tracked with mode-flag dispatcher (`--gate`, `--regression`, `--canary`, `--all`, `--b2`, `--help`); consolidates v1.2's `/tmp/bench-v1.2/run.sh` selectors into semantic groupings.
- [x] **BENCH-02** ✓ v1.3 — `bench/fixtures/` holds versioned bug fixtures (`bug_lastchar.fs`, `bug_average.fs`, `bug_divide_zero.fs`); old untracked `bench-fixtures/` removed.
- [x] **BENCH-03** ✓ v1.3 — `bench/baseline.json` records 8 test entries (T6 × 32B/72B, W1/W2 × 32B, T1/T5 canaries, B2 × 32B/72B) with `step_count`, `step_count_max`, `pass`, `regression` (where applicable), and notes.
- [x] **BENCH-04** ✓ v1.3 — `bench/run.sh --gate` runs the 8-test regression subset (~115s wall-clock), parses logs via grep + jq, diffs against `baseline.json`, prints per-test PASS/FAIL summary, exits non-zero on regression. SC1 verified both positively (current binary → exit 0) and negatively (tightened baseline → exit 1, restored → exit 0).
- [x] **BENCH-05** ✓ v1.3 — `documentation/bench.md` (190 lines, 11 sections) covers fixture naming convention, prompt-design guidance (avoid explicit tool naming per 09.1-04 discovery), how to add a new test, how to update baseline after intentional fix (with v1.3 PERF-03 worked example), and hang-contingency for `mlx_lm.server` 32B.

### Performance

- [x] **PERF-01** ✓ v1.3 — `defaultSystemPrompt` cut from 1689 chars (committed baseline; ROADMAP estimate of "1500" was off by ~190) to **783 chars** (54% reduction, Path C ≤800 target achieved). Iteratively validated by `bench/run.sh --gate` after each prompt-edit cycle (13 cycles, 75 min wall-clock). All 8 gate tests stayed green throughout.
- [x] **PERF-02** ✓ v1.3 — 09.1-05's `lastEditPath` loop-injection primitive extended with `lastReadHint: (string * string) option` parameter in `AgentLoop.fs:runLoop`. After successful `read_file`, parses the header's first line for `truncated]` or `out-of-range]` substrings; `buildMessages` appends a System-role `[POST-READ HINT]` message at END of message list (post-user position) when `Some (path, kind)`. Truncated arm: "pick a smaller window — set end_line - start_line < 50". Out-of-range arm: "choose a start_line ≤ total_lines and read again." 1 new `testCaseAsync` in existing `AgentLoopTests.fs` (242→243 tests).
- [x] **PERF-03** ✓ v1.3 — B2 fixture (divide-by-zero misdiagnosis) recovered to v1.1 baseline behavior on **BOTH** 32B and 72B (SC4 required only one model; both delivered exceeds requirement). `bench/baseline.json` B2_32b and B2_72b entries flipped from `pass: false, regression: true` to `pass: true` (regression field removed, note updated with verbatim model thought lines). v1.2 audit's prompt-length attention-shift hypothesis confirmed: 54% prompt reduction was sufficient on its own; no surgical B2 hint needed.

## Bonus Outcomes (Rule 3 auto-fixes during PERF-01)

Two pre-existing bugs in `src/BlueCode.Cli/Adapters/FsToolExecutor.fs` were uncovered during Phase 11-02's iterative prompt-shrink validation. Both were blocking gate-pass on shrunk prompt; fixed under workflow's Rule 3 (auto-fix blockers) discipline.

- **`edit_file` empty `old_string` infinite-loop guard** — when 32B model attempted append-style edit with empty `old_string`, the IndexOf loop never terminated. Now returns `Failure(1, "oldString must be non-empty")`.
- **`grep_search` file-path acceptance** — 72B's strong prior of using user-prompt file paths cannot be overridden by schema annotations alone (research insight from PERF-01 iteration). Tool now accepts both directory and file paths; if path resolves to a file, searches that single file.

These are not v1.3 requirements but were necessary for PERF-01's gate-green validation.

## Milestone Summary
