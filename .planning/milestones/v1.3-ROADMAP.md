## Overview

v1.3 formalized v1.2's behavioral wins as a repo-tracked regression suite, then used that suite to validate a system-prompt shrink that addressed B2's divide-by-zero misdiagnosis and created headroom for future tool additions. Phase 10 moved the bench harness from `/tmp/` into the repo with a `bench/run.sh --gate` mode that exits non-zero on regression. Phase 11 executed and validated the system-prompt shrink, leveraging both the gate and the 09.1-05 loop-injection primitive (extended in Phase 11-01 to post-`read_file` truncated/out-of-range cases) to move contextual hints out of the base prompt.

## Milestone Summary

**Decimal Phases:** None — v1.3 had no `/gsd:insert-phase` insertions.

**Key Decisions:**

- **Bench gate is the canonical regression detector** — `bench/run.sh --gate` runs the 8-test subset (T6 × 32B/72B, W1/W2 × 32B, T1/T5 canaries, B2 × 32B/72B) in ~115s; jq-based JSON diff vs `bench/baseline.json`; 3-branch verdict (`is_regression` first → `step_count_max` → `baseline.pass + actual_exit`).
- **Regression whitelist via `regression: true` field** — known broken entries (B2 at v1.3 start) always PASS the gate until manually flipped; recovery decision is human, not auto-detected. PERF-03 demonstrated the recovery flip workflow.
- **Path C / Path D escape hatch discipline for prompt shrink** — Path C (≤800 chars) was the goal; Path D (≤1000 chars with documented rationale) was a pre-defined escape hatch. Path C achieved at 783 chars; Path D not invoked.
- **`(string * string) option` parameter shape for post-tool hints** — `lastReadHint` mirrors 09.1-05's `lastEditPath` discipline (function parameter, not a Domain.fs record field). Same lifecycle: single-iteration scope, cleared on next loop.
- **`[POST-READ HINT]` two-arm logic** — separate text for `truncated` vs `out-of-range` (corrective actions differ; specificity matters for T6 behavioral quality).
- **Bench fixture prompt discipline** — fixtures avoid explicit tool naming except W1's deliberate `using write_file` exception (validates 09.1-05 loop-injection regression). Documented in `bench.md` and the new howto `design-llm-agent-bench-fixtures.md`.
- **`is_regression` first-branch verdict** — gate's three-branch logic puts regression-whitelist *first* (vs the originally-proposed fourth-branch "regression recovery" detector that would have fired on every B2 run, breaking SC1; caught by plan-checker iteration 1/3).
- **Empirical floor calibration** — research suggested T6_72b would be 5 steps; live measurement gave 4. Lesson: research defaults are starting points; live runs determine baseline.
- **Two Rule 3 auto-fixes in FsToolExecutor.fs** (Phase 11-02 in flight) — `edit_file` empty-`old_string` infinite-loop guard + `grep_search` file-path support. Surfaced as bench-blockers during prompt-shrink iteration; fixed under Rule 3 (auto-fix blockers) discipline.

**Issues Resolved:**

- **B2 misdiagnosis recovered on both 32B and 72B** — v1.2's audit hypothesis (prompt-length attention shift) confirmed empirically. 54% prompt reduction was sufficient on its own; no surgical B2 hint needed.
- **Bench harness no longer ephemeral** — moved from `/tmp/bench-v1.2/run.sh` (lost on `/tmp/` cleanup) to repo-tracked `bench/run.sh` with versioned fixtures and `--gate` regression mode.
- **T6 step count deterministic** — both 32B and 72B now reliably complete T6 in 3 steps (`grep_search → read_file → final`); previously flaky 4-5 steps with occasional MaxLoops.
- **`edit_file` empty `old_string` infinite loop** — pre-existing bug since v1.2 (32B append attempts triggered infinite IndexOf loop); guarded with `Failure(1, "oldString must be non-empty")`.
- **`grep_search` file-path acceptance** — 72B's strong prior of using user-prompt file paths cannot be overridden by schema annotations alone; tool now accepts both directory and file paths.
