**The Rubric (research Q4 verbatim — this rubric is the sole scoring authority; do NOT diverge from research Q4 wording):**

For each fixture, score 5 binary criteria (C1-C5 per research Q4). Each is 0 or 1. Sum across all fixtures gives the grand total (15 max for 3 fixtures); apply the band table below to map to the §5 5-point scale.

| # | Criterion | Score 1 if... | Score 0 if... |
|---|-----------|---------------|---------------|
| C1 | Idiomatic pattern present | The targeted pattern appears in the implementation: `\|>` in pipeline fixture; `match` over DU in dupatternmatch fixture; `Option.map`+`Option.defaultValue` in optionhandling fixture | Pattern absent (sequential `let` bindings without `\|>`; `if shape.IsCircle` instead of `match`; `if result.IsSome then result.Value` instead of `Option.map`) |
| C2 | Anti-pattern absent | Body avoids: mutable accumulator (`let mutable` / `<-`); `if shape.IsCircle` (type-discriminator if-chain); `.Value` after `.IsSome`; nested `match` where `bind` was requested | Any anti-pattern listed is present |
| C3 | Type signatures preserved | Function signature exactly matches the skeleton (parameter names, types, return type annotation) | Signature mutated (e.g., `(nums: int list) : int` changed to `nums` without annotation) |
| C4 | Code structurally valid F# | No obvious syntax errors visible in transcript; agent's edit_file content parses as F# (verifiable by reading transcript and/or recompiling the post-run `.fs` file with `dotnet fsi <file>`) | Compile errors present, or content is not valid F# |
| C5 | Task goal met | The implementation does what the task description says (pipeline: filters/squares/sums/×2 per task; DU: all 3 cases handled producing area; optionhandling: parses + doubles + defaults to 0 on failure) | Task goal not met (wrong arithmetic, missing cases, wrong default) |

**Note on PASS/FAIL examples:** PASS/FAIL examples for each criterion must be derived from the actual fixture function signatures documented in `28-02-SUMMARY.md`, NOT from research Q3 prototypes (which used different function names: `processNumbers` / `describeShape` / `safeDivide`+`formatResult` vs the actual fixtures `transform` / `area` / `safeDouble`). Before scoring, the executor reads `28-02-SUMMARY.md` to extract the actual function names + signatures and writes per-fixture PASS/FAIL examples in the SUMMARY that match those signatures. Research Q4 disambiguation examples (lines 415-427) illustrate the SHAPE of PASS/FAIL judgments but use prototype function names; rewrite them to match the real fixtures.

**Scoring procedure** (for each of the 3 fixtures):

1. Read the archived transcript: `cat .planning/phases/28-.../transcripts/fs_idiomatic_<base>.transcript.txt`. Locate the `===== POST-RUN <fs-file> =====` block (handler appended this).
2. Extract the post-run `.fs` content into a scratch file.
3. Re-compile-check it: `dotnet fsi /tmp/<base>-postrun.fs`. Note PASS/FAIL → criterion 5.
4. Apply criteria 1-4 by inspection. Be honest — this is the data that drives the §5 score.

**Aggregate scoring (research Q4 sum-then-scale; reproduced verbatim — this is the sole authoritative scoring rule):**

```
per_fixture_score = sum(C1..C5)              # 0-5 per fixture
grand_total = sum(per_fixture_score over 3 fixtures)   # 0-15 for 3 fixtures × 5 criteria
mapped_score = band_lookup(grand_total)      # integer 0-5 to put in §5 row
```

**Band table** (research Q4 verbatim, lines 442-446):

| Grand total (out of 15) | §5 sub-score |
|-------------------------|--------------|
| ≥12 | 5/5 |
| 9-11 | 4/5 |
| 6-8 | 3/5 |
| 3-5 | 2/5 |
| 1-2 | 1/5 |
| 0 | 0/5 |

**Worked example:** Per-fixture totals [5, 5, 0] → grand_total = 10 → band `9-11` → mapped_score = **4/5**.
(Note: this disagrees with a naive `round(average)` which would yield 3/5; always use the band table, never an arithmetic mean.)

**Classification rules:**

- `passed_disprove_1of5` → `mapped_score >= 3` (1/5 was a Python-transcript artifact; F# generation is at least mid-tier)
- `passed_confirm_1of5` → `mapped_score <= 1` (covers 0 and 1; F# generation quality is genuinely low — confirms the v2.3 hedge)
- `passed_inconclusive` → `mapped_score == 2` (intermediate; user judgment required at 28-06)
