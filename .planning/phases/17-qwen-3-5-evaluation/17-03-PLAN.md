## §6 Decision matrix (KEEP / SWITCH / SHIP-BOTH)

Three criteria, each with explicit thresholds. The verdict is the conjunction.

### 6.1 Correctness (mandatory)

A pair is correctness-acceptable iff:
- ALL `--gate` tests (T6_32b, T6_72b, W1_32b, W2_32b, T1_32b, T5_72b, B2_32b, B2_72b) pass `bench/run.sh --gate` exit 0 (or would, when re-keyed for 35B/122B). Gate authority is `bench/run.sh --gate` exit code, not subjective.

- ZERO `<think>` token leakage in any --all invocation log (§5.5 grep).
- ZERO multi-turn degradation regressions (§5.4): no test exceeded its `step_count_max` despite loop-injection.

If any of the above fails for the candidate (35B/122B), it is correctness-unacceptable → KEEP verdict regardless of latency.

### 6.2 Latency (advisory; tiebreaker if correctness equal)

A pair is latency-improved iff:
- Median elapsed across all tests improves by ≥ 20% (sum of new elapsed / sum of baseline elapsed ≤ 0.80).
- No single test regresses by > 100% (i.e., no test takes >2× longer).

If 35B/122B is latency-improved AND correctness-acceptable → SWITCH-favored.
If 35B/122B is correctness-acceptable but latency-similar (within ±20%) → SWITCH-neutral; verdict KEEP unless a separate qualitative argument is made (smaller memory footprint, future model availability, etc. — must be enumerated).

### 6.3 Memory budget (advisory)

The 35B+122B 4-bit pair uses ~89.5 GB of unified memory vs 32B+72B's ~58.8 GB (research §Memory Budget §Simultaneous load comparison). A ~30 GB tighter headroom is a structural risk — observable as Chrome/Xcode causing OOM during cold-start. If 17-02-LOAD-TEST.md §6 reported peak RSS exceeded research projections by > 10%, this is a memory-risk flag against SWITCH.

### 6.4 SHIP-BOTH (out of scope for this phase)

If 35B is materially better on small tasks (T1, T2, T6 small) AND 122B is materially better on hard tasks (T5, T7, harder reasoning), SHIP-BOTH (per-task routing) is a third option. But this requires:
- Plumbing in `Router.fs` to route by task type, not just model size — non-trivial code change.
- Running both new pairs alongside old pairs — exceeds memory budget.

**SHIP-BOTH is OUT OF SCOPE for Phase 17.** If §4-§5 data suggests SHIP-BOTH is desirable, this doc records the observation here and explicitly defers it to v2.1+ as a roadmap candidate. The user can re-open via a future phase.

### 6.5 Decision rule

| Correctness | Latency | Memory | Verdict |
|-------------|---------|--------|---------|
| FAIL        | -       | -      | KEEP    |
| PASS        | improved (≥20%) | acceptable (no >10% RSS overage) | SWITCH |
| PASS        | improved (≥20%) | risky (RSS >10% over projection)  | KEEP (with note: "rejected on memory risk") |
| PASS        | neutral / regressed | -                            | KEEP    |
| PASS, with strong per-task split | - | - | KEEP + record SHIP-BOTH as v2.1 candidate |
