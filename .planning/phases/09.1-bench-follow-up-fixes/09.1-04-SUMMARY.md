## Next Phase Readiness

**Plan 09.1-05** recommended with a code-level intervention. Two options:

- **Option A (preferred — loop-level):** After a successful `edit_file`, the next agent loop iteration injects a synthetic constraint into the context (e.g., append a system message: "edit_file completed. Proceed directly to `final` or the next `edit_file`. Do NOT call write_file."). This intercepts at the loop/context-injection level, bypassing user-prompt priority. Implementation: `AgentLoop.runLoop` or `ToolExecutor.dispatchTool` — detects the last-action = edit_file condition and filters/blocks write_file in the next response.

- **Option B (schema-level — larger blast radius):** Extend the schema validator to reject `write_file` on the same path immediately following an `edit_file` success. Requires Domain changes to track last action. Forces the model to choose `final` even when user prompt names write_file.

Option A is preferred because it has lower blast radius (loop-level injection, no Domain changes) and can be implemented without changing the schema or the model's perceived action space.
