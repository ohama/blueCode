<objective>
Validate the v1.2-audit hypothesis that B2's divide-by-zero misdiagnosis is prompt-length attention shift. With Plan 11-02's shrunk prompt deployed, run `bench/run.sh --b2` (~30s), inspect both 32B and 72B logs, and update `bench/baseline.json` to reflect the post-shrink reality. If at least one model correctly diagnoses "empty list causes DivideByZeroException" instead of "integer truncation", flip its baseline entry from regression to pass. If neither recovers, document the partial outcome — the hypothesis is wrong and a v1.4 follow-up plan can target B2 directly.

Purpose: PERF-03 (B2 recovery validates the audit hypothesis and finalizes the bench baseline for v1.3 milestone close). Also, the bench-driven discipline established in Phase 10 means we have the structural answer to "did the prompt shrink fix B2?" — we run the fixture and read the logs.

Output: One file modified (`bench/baseline.json`), one final `bench/run.sh --gate` run with the updated baseline producing `GATE PASS (8/8)`, and a SUMMARY documenting the diagnosis quality observed (with quoted excerpts from the logs).
</objective>

**Step A — Run B2 on the post-shrink binary:**

```bash
bash bench/run.sh --b2
```

This produces `bench/runs/<timestamp>/b2_32b.log` and `b2_72b.log` (and `.meta` files). Wall clock: ~30s. The fixture is `bench/fixtures/bug_divide_zero.fs`; the prompt does NOT name a tool (per BENCH-05 / 09.1-04 guidance).

**Step B — Inspect the logs:**

For each of the two log files, read the model's `thought` lines and the final answer. The recipe:

```bash
LATEST_B2_DIR=$(ls -dt bench/runs/*/ | head -1)
echo "=== B2 32B log ===" ; cat "$LATEST_B2_DIR/b2_32b.log" | grep -A 1 'thought\|FINAL\|answer' | head -80
echo "=== B2 72B log ===" ; cat "$LATEST_B2_DIR/b2_72b.log" | grep -A 1 'thought\|FINAL\|answer' | head -80
```

For each model, classify the diagnosis as ONE of:
- **Recovered**: answer contains "empty list" / "empty input" / "List.length xs = 0" / "len = 0" + "DivideByZeroException" or "/0" — the actual root cause.
- **Misdiagnosed**: answer says "integer truncation" / "rounding" / "int division loses fractional" — the v1.2 incorrect diagnosis.
- **Other**: answer mentions both, mentions neither, or is genuinely ambiguous — record the verbatim text in SUMMARY for human judgment.

The Phase 11 SC4 acceptance is "**at least one model correctly identifies empty-list cause**" — partial recovery (one of two) is sufficient.

**Step C — Update `bench/baseline.json`:**

Read the current baseline structure (preserve all fields; only modify the B2 entries). The current B2 entries look like:

```json
"B2_32b": {
  "step_count": 2,
  "step_count_max": 3,
  "pass": false,
  "regression": true,
  "expected_diagnosis": "empty list causes DivideByZeroException",
  "actual_diagnosis": "integer truncation",
  "note": "KNOWN regression since v1.2 prompt growth. PERF-03 (Phase 11) target. Gate must NOT fail on this until PERF-03 lands."
}
```

For each B2 entry, apply the matching update:

**Case 1 — Recovered (model correctly identifies empty list):**
```json
"B2_32b": {
  "step_count": <observed>,
  "step_count_max": <observed + 1>,
  "pass": true,
  "regression": false,
  "expected_diagnosis": "empty list causes DivideByZeroException",
  "actual_diagnosis": "empty list causes DivideByZeroException",
  "note": "Recovered post-PERF-01 prompt shrink (Plan 11-02). Validates v1.2 audit's prompt-length attention-shift hypothesis. Updated by Plan 11-03 on <YYYY-MM-DD>."
}
```
Set `step_count_max` to `observed + 1` to allow normal model variance without false-failing the gate.

**Case 2 — Misdiagnosed (still says "integer truncation" or similar wrong diagnosis):**
```json
"B2_<model>": {
  "step_count": <observed>,
  "step_count_max": 3,
  "pass": false,
  "regression": true,
  "expected_diagnosis": "empty list causes DivideByZeroException",
  "actual_diagnosis": "<verbatim model output, e.g. 'integer truncation in average'>",
  "note": "Persists post-PERF-01 prompt shrink. Hypothesis disproved for this model — prompt length is not the only factor. v1.4 follow-up: surgical B2 hint or fixture rephrasing. Gate continues to PASS this entry under regression-tracked logic."
}
```

**Case 3 — Other (ambiguous):**
Default to the Misdiagnosed shape but record the verbatim text in `actual_diagnosis` and add a `note` line beginning with `"Manual review needed: ..."`. Phase verifier or operator can decide the disposition.

- `jq -r '.tests.B2_32b.regression, .tests.B2_72b.regression' bench/baseline.json` — values reflect the observed disposition.

**Step D — Final gate run on the UPDATED baseline:**

```bash
bash bench/run.sh --gate
```

Must exit 0 with `GATE PASS (8/8)`. This is the v1.3-final regression gate. If a B2 entry was flipped from `regression: true` to `regression: false`, the gate now validates the B2 step count against `step_count_max` like any other entry — so the `step_count_max` must accommodate the observed reality. If gate FAILs because B2 step count exceeded `step_count_max`, raise `step_count_max` (don't flip back to `regression: true` — the model recovered, that's what matters; just give it more step slack).

**If the gate FAILs on a non-B2 entry**, that's a real regression introduced by Plan 11-02's prompt shrink that wasn't caught during 11-02's iteration cycle. Halt; surface as `## CHECKPOINT REACHED` to the orchestrator with options:
- Revert Plan 11-02 partially and re-run.
- Update the failing entry's baseline if the new step count is acceptable behavior.
- Escalate.
