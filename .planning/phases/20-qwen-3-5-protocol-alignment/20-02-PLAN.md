<objective>
Add a `reasoning_content` fallback to the LLM response content extraction path. When the LLM
returns `choices[0].message.content` as null or empty string, fall back to reading
`choices[0].message.reasoning_content` before declaring `LlmUnreachable`. This handles a documented
Qwen 3.5 / mlx_lm.server response shape variation (qwen35-install.md §5.3 + Appendix A row 5).

Purpose: Eliminate a latent failure mode where Qwen 3.5 emits the actual response in
`reasoning_content` (with `content` empty) — currently this propagates an empty string downstream
and produces an `InvalidJsonOutput` after the parse retry. The fallback is defensive: under
`enable_thinking: false` (the canonical config) the path is rarely triggered, but it costs nothing
and removes a documented gotcha.

Output: 4 atomic commits (refactor extractContent → public helper, add fallback, add tests, update
docs), bench gate 6/6 PASS, test suite reaches ≥263/1/0.
</objective>

       /// Tries choices[0].message.content first; if that is null/empty/missing, falls back to

       /// the path is rare but defensively supported.
       let extractContentFromJson (responseJson: string) : string option =
           let pickStringField (msg: JsonElement) (fieldName: string) : string option =
               match msg.TryGetProperty(fieldName) with
               | true, el when el.ValueKind = JsonValueKind.String ->
                   let s = el.GetString()
                   if System.String.IsNullOrEmpty(s) then None else Some s
               | _ -> None

               use doc = JsonDocument.Parse(responseJson)
               let msg = doc.RootElement.GetProperty("choices").[0].GetProperty("message")
