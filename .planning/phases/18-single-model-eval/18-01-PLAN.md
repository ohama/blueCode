<objective>
Cleanly unload the 35B service from launchd, verify the 122B service stays healthy and responsive on port 8001, and capture a precise memory profile (PhysMem, Compressor, RSS for both processes) before and after the unload. The output is `18-01-MEMORY-PROFILE.md` — empirical evidence for the ROADMAP §SC4 memory criteria (PhysMem unused ≥ 5 GB, Compressor < 1 GB) and a precondition gate for 18-02's 122B-only bench.

Purpose: Phase 18's whole hypothesis is that 35B can be dropped without operational regression. The first thing to verify is that the unload itself is clean and the 122B alone stays healthy. If 35B unload is botched (auto-restarts, port 8000 stays bound, 122B degrades), 18-02's bench results would be unreliable. This plan is the test-bed setup + sanity check.

Output:
- `.planning/phases/18-single-model-eval/18-01-MEMORY-PROFILE.md` (≥ 60 lines) — the empirical record. Mirrors the shape of `17-02-LOAD-TEST.md` (pre/post tables + observations + hypothesis section).
- 35B service is unloaded; system is in single-122B state, ready for 18-02.
- Atomic commit per CLAUDE.md commit-protocol convention.

Reversibility: This plan does NOT touch Core, the bench script, or any documentation outside `.planning/phases/18-single-model-eval/`. The 35B unload is reversed by `launchctl load -w` (handled at the end of 18-03 if verdict is KEEP-DUAL or CONDITIONAL).
